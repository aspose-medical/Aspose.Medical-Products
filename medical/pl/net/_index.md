<p><strong>Aspose.Medical for .NET</strong> jest czystą biblioteką klas .NET przeznaczoną do pracy z plikami DICOM (Digital Imaging and Communications in Medicine). Umożliwia deweloperom czytanie, zapisywanie, modyfikowanie, anonimizowanie, transkodowanie i renderowanie danych medycznego obrazowania, serializację do DICOM JSON i DICOM XML oraz wymianę badań z innymi systemami poprzez DIMSE i DICOMweb, bez żadnego zewnętrznego oprogramowania ani natywnych zależności.</p>

<p>Biblioteka została napisana w całości w zarządzanym C# i działa na .NET 10 w systemach Windows, Linux i macOS. Nie zawiera natywnych plików binarnych ani pakietów NuGet firm trzecich, dzięki czemu jest wdrażana jako pojedynczy zestaw w każdej aplikacji .NET, od narzędzia desktopowego po kontener w chmurowym systemie opieki zdrowotnej.</p>

<p><strong>Kluczowe funkcje:</strong>
<ul>
    <li>Odczyt i zapis plików DICOM z pliku, strumienia lub potoku, synchronnie lub asynchronicznie, z pełnym wsparciem dla wszystkich standardowych elementów danych i reprezentacji wartości.</li>
    <li>Zarządzaj pamięcią przy dużych plikach: wczytaj każdy element, odłóż duże elementy do czasu ich użycia lub pomiń je i odczytaj tylko metadane.</li>
    <li>Odczyt i edycja dowolnego elementu danych, w tym sekwencji i prywatnych tagów, z obsługą zestawów znaków dla tekstu nie‑ASCII.</li>
    <li>Anonimizuj pliki DICOM przy użyciu profili poufności DICOM PS 3.15, z opcjami zachowywania UID‑ów, dat, identyfikatorów urządzeń i instytucji oraz cech pacjenta.</li>
    <li>Transkoduj pomiędzy składniami transferowymi: JPEG, JPEG‑LS, JPEG 2000, HTJ2K, JPEG XL i RLE, przy czym każdy kodek jest zaimplementowany w .NET.</li>
    <li>Renderuj klatki do pikseli BGRA z zastosowaniem LUT modalności, LUT VOI (okno i poziom) oraz nakładek stosowanych przez renderer.</li>
    <li>Serializuj zestawy danych do modelu DICOM JSON (PS3.18) oraz DICOM XML (PS3.19) i z powrotem, włączając asynchroniczne strumieniowanie oraz wtyczkowe ładowanie danych masowych.</li>
    <li>Komunikuj się przez DIMSE jako klient i serwer: C‑ECHO, C‑STORE, C‑FIND, C‑MOVE, C‑GET, usługi N oraz TLS.</li>
    <li>Zapytaj listę prac modalności, zgłaszaj MPPS i przydzielaj zadania przy użyciu elementów pracy UPS‑RS, zarówno jako klient, jak i serwer.</li>
    <li>Wyszukuj, pobieraj i wysyłaj badania na dowolnym serwerze DICOMweb przy użyciu typowanego klienta dla QIDO‑RS, WADO‑RS, STOW‑RS, renderowanych obrazów, WADO‑URI oraz usług przepływu pracy.</li>
    <li>Stwórz własny serwer DICOMweb: QIDO‑RS, WADO‑RS, STOW‑RS oraz usługi przepływu pracy na ASP.NET Core lub dowolnym innym hoście HTTP, z własnym magazynem danych za nimi.</li>
</ul>
</p>

<p>Aspose.Medical for .NET jest samodzielny. Nie wymaga instalacji żadnego przeglądarki DICOM, oprogramowania do obrazowania medycznego ani natywnych kodeków. Pasuje do systemów informatyki zdrowotnej, integracji PACS, platform telemedycyny oraz każdej aplikacji, która musi niezawodnie przetwarzać dane DICOM.</p>

   <div class="col-lg-12">
    <h2 class="h2title">
     Czysta biblioteka .NET – Zero zależności
    </h2>
    <p>
     Aspose.Medical for .NET jest napisany w całości w zarządzanym C# i dystrybuowany jako pojedynczy zestaw bez natywnych plików binarnych i pakietów NuGet firm trzecich. Inne biblioteki obrazowania medycznego polegają na natywnych kodekach lub zewnętrznych narzędziach; ta nie. Wszystkie kodeki kompresji obrazu (JPEG, JPEG‑LS, JPEG 2000, HTJ2K, JPEG XL, RLE) są zaimplementowane w .NET, dzięki czemu biblioteka zachowuje się tak samo na Windows, Linux i macOS. To czyni ją odpowiednią dla kontenerów, środowisk chmurowych i wszelkich wdrożeń, gdzie instalacja natywnych bibliotek nie jest możliwa. Pakiet celuje w .NET 10.
    </p>
   </div>
   <div class="col-lg-12">
    <h2 class="h2title">
     Anonimizuj pliki DICOM w celu zgodności z wymogami prywatności
    </h2>
    <p>
     Prywatność pacjenta jest kluczowym wymogiem w aplikacjach opieki zdrowotnej. Aspose.Medical for .NET anonimizuje dane DICOM przy użyciu profili poufności DICOM PS 3.15. Możesz usunąć lub zastąpić informacje identyfikujące pacjenta, zachowując wartość kliniczną danych obrazowych, a także wybrać, co dany profil zachowuje: bezpieczne prywatne atrybuty, UID‑y, identyfikatory urządzeń i instytucji, cechy pacjenta oraz informacje czasowe w ujęciu longitudinalnym. <a href="/medical/net/anonymization/">Strona anonimizacji DICOM</a> przedstawia szczegółowo opcje profili.
    </p>
    <div class="codeblock" id="code">
     <h3>
      Anonimizuj plik DICOM - C#
     </h3>
     <pre><code class="cs">// Load the DICOM file
DicomFile dicomFile = DicomFile.Open("patient_scan.dcm");

// Basic Application Level Confidentiality Profile of DICOM PS 3.15
ConfidentialityProfile profile = ConfidentialityProfile.CreateDefault(ConfidentialityProfileOptions.BasicProfile);
Anonymizer anonymizer = new(profile);

// Anonymize into a new file and save it
DicomFile anonymized = anonymizer.Anonymize(dicomFile);
anonymized.Save("anonymized_scan.dcm");</code></pre>
    </div>
   </div>
   <div class="col-lg-12">
    <h2 class="h2title">
     Renderuj ramki DICOM w .NET C#
    </h2>
    <p>
     Aspose.Medical for .NET renderuje ramkę DICOM do 32‑bitowego obrazu pikseli BGRA. Renderer stosuje interpretację fotometryczną, LUT modalności oraz LUT VOI (okno i poziom) z zestawu danych i rysuje nakładki, dzięki czemu wynik odpowiada temu, co pokazuje przeglądarka. Piksele są następnie Twoje: skopiuj je do bufora i przekaż dowolnej bibliotece obrazowania, aby zapisać PNG, JPEG lub TIFF. Jedynym enkoderem obrazu wbudowanym w bibliotekę jest PNM. Strony konwersji pokazują pełną ścieżkę dla <a href="/medical/net/dicom-to-png/">PNG</a>, <a href="/medical/net/dicom-to-jpg/">JPEG</a> i <a href="/medical/net/dicom-to-tiff/">TIFF</a>.
    </p>
    <div class="codeblock" id="code">
     <h3>
      Renderuj ramkę DICOM - C#
     </h3>
     <pre><code class="cs">// Load the DICOM file
DicomFile dicomFile = DicomFile.Open("chest_xray.dcm");

// Render the first frame; LUTs and overlays are applied by the renderer
using PixelImage&lt;Bgra32&gt; image = dicomFile.RenderImage(0);

// Copy the pixels out and hand them to an imaging library
Bgra32[] pixels = new Bgra32[image.Width * image.Height];
image.CopyPixelsTo(pixels);</code></pre>
    </div>
   </div>
   <div class="col-lg-12">
    <h2 class="h2title">
     Transkoduj między składniami transferu
    </h2>
    <p>
     Systemy obrazujące i archiwa wymagają określonych składni transferu DICOM. Aspose.Medical for .NET transkoduje pomiędzy formatami nieskompresowanymi, JPEG Baseline, JPEG Extended, JPEG Lossless, JPEG‑LS, JPEG 2000, HTJ2K (High‑Throughput JPEG 2000), JPEG XL i RLE. HTJ2K i JPEG XL są dwoma najnowszymi opcjami w standardzie DICOM i są tu zaimplementowane w .NET tak jak wszystkie pozostałe kodeki. Transkodowanie ma znaczenie przy integracji z PACS, rozmiarze archiwum oraz kompatybilności między systemami. Zobacz <a href="/medical/net/dicom-transfer-syntax-conversion/">stronę konwersji składni transferu</a> oraz <a href="/medical/net/jpeg2000/">stronę JPEG 2000</a>.
    </p>
    <div class="codeblock" id="code">
     <h3>
      Transkoduj DICOM do HTJ2K - C#
     </h3>
     <pre><code class="cs">// Load existing DICOM file
DicomFile dicomFile = DicomFile.Open("input.dcm");

// Transcode to High-Throughput JPEG 2000, lossless
DicomFile transcoded = dicomFile.Transcode(TransferSyntax.HTJ2KLossless);

// Save the transcoded file
transcoded.Save("output.dcm");</code></pre>
    </div>
   </div>
   <div class="col-lg-12">
    <h2 class="h2title">
     Serializacja DICOM do JSON i XML
    </h2>
    <p>
     Systemy opieki zdrowotnej wymieniają dane za pośrednictwem usług sieciowych, dlatego Aspose.Medical for .NET serializuje zestawy danych DICOM do modelu DICOM JSON (PS3.18) i DICOM XML (PS3.19), a także odczytuje je z powrotem do zestawów danych. Serializatory działają na ciągach znaków, strumieniach i potokach, synchronicznie i asynchronicznie, a sekwencja zestawów danych może być odczytywana kolejno, bez konieczności trzymania całego dokumentu w pamięci. Odwołania do danych masowych są rozwiązywane przez wtyczkowy loader, więc duże dane pikseli mogą pozostawać poza dokumentem. Zobacz strony <a href="/medical/net/dicom-to-json/">DICOM do JSON</a> oraz <a href="/medical/net/dicom-to-xml/">DICOM do XML</a>.
    </p>
    <div class="codeblock" id="code">
     <h3>
      Serializuj DICOM do JSON i XML - C#
     </h3>
     <pre><code class="cs">// Load the DICOM file
DicomFile dicomFile = DicomFile.Open("patient_scan.dcm");
Dataset dataset = dicomFile.Dataset;

// Serialize the dataset to JSON (DICOM JSON Model) and to DICOM XML
string json = DicomJsonSerializer.Serialize(dataset, writeIndented: true);
string xml = DicomXmlSerializer.Serialize(dataset);

// Parse both back into datasets
Dataset? fromJson = DicomJsonSerializer.Deserialize(json);
Dataset fromXml = DicomXmlSerializer.Deserialize(xml);</code></pre>
    </div>
   </div>
   <div class="col-lg-12">
    <h2 class="h2title">
     Sieciowanie DICOM przez DIMSE
    </h2>
    <p>
     Aspose.Medical for .NET komunikuje się bezpośrednio z innymi systemami DICOM. Biblioteka udostępnia klienta i serwer DIMSE dla C‑ECHO, C‑STORE, C‑FIND, C‑MOVE i C‑GET, wraz z usługami N, negocjacją połączenia z kontekstami prezentacji i rolami, asynchronicznymi oknami operacji, negocjacją tożsamości użytkownika oraz TLS. Żądania są kolejkowane w ramach połączenia i obsługiwane przez zarejestrowane przez Ciebie obsługi, więc węzeł store‑and‑forward, proxy zapytań czy testowy SCP to kwestia kilku klas. <a href="/medical/net/modality-worklist/">Strona listy prac modalności</a> pokazuje listę prac i przepływ MPPS po obu stronach. <a href="https://docs.aspose.com/medical/net/developer-guide/dicom-networking/">Przewodnik po sieciowaniu DICOM</a> obejmuje pełne API.
