<p><strong>Aspose.Medical pour .NET</strong> est une bibliothèque de classes .NET pure permettant de travailler avec des fichiers DICOM (Digital Imaging and Communications in Medicine). Elle permet aux développeurs de lire, écrire, modifier, anonymiser, transcoder et rendre des données d'imagerie médicale, de les sérialiser en DICOM JSON et DICOM XML, et d'échanger des études avec d'autres systèmes via DIMSE, sans aucun logiciel externe ni dépendance native.</p>

<p>La bibliothèque est entièrement écrite en C# géré et s'exécute sur .NET 10 sous Windows, Linux et macOS. Il n'y a aucun binaire natif ni aucun package NuGet tiers, de sorte que la bibliothèque se déploie sous la forme d'un seul assembly dans n'importe quelle application .NET, depuis un outil de bureau jusqu'à un conteneur dans un système de santé cloud.</p>

<p><strong>Fonctionnalités clés :</strong>
<ul>
    <li>Lire et écrire des fichiers DICOM depuis un fichier, un flux ou un pipe, de manière synchrone ou asynchrone, avec un support complet de tous les éléments de données standard et des représentations de valeur.</li>
    <li>Contrôler la mémoire sur les fichiers volumineux : charger chaque élément, différer les gros éléments jusqu'à leur utilisation, ou les ignorer et ne lire que les métadonnées.</li>
    <li>Lire et modifier tout élément de données, y compris les séquences et les balises privées, avec prise en charge du jeu de caractères pour le texte non ASCII.</li>
    <li>Anonymiser les fichiers DICOM avec les profils de confidentialité du DICOM PS 3.15, avec des options pour conserver les UID, les dates, les identifiants d'appareil et d'institution ainsi que les caractéristiques du patient.</li>
    <li>Transcoder entre les syntaxes de transfert : JPEG, JPEG-LS, JPEG 2000, HTJ2K, JPEG XL et RLE, chaque codec étant implémenté en .NET.</li>
    <li>Rendre les images en pixels BGRA avec le LUT de modalité, le LUT VOI (fenêtre et niveau) et les superpositions appliquées par le moteur de rendu.</li>
    <li>Sérialiser les jeux de données vers le modèle DICOM JSON (PS3.18) et vers le DICOM XML (PS3.19) et inversement, incluant le streaming asynchrone et le chargement extensible de données volumineuses.</li>
    <li>Communiquer via DIMSE avec un client et un serveur : C‑ECHO, C‑STORE, C‑FIND, C‑MOVE, C‑GET, les services N et TLS.</li>
</ul>
</p>

<p>Aspose.Medical pour .NET est autonome. Aucun visualiseur DICOM, aucun logiciel d'imagerie médicale et aucun codec natif ne sont requis. Il convient aux systèmes informatiques de santé, à l'intégration PACS, aux plateformes de télémédecine et à toute application nécessitant de traiter les données DICOM de manière fiable.</p>

   <div class="col-lg-12">
    <h2 class="h2title">
     Bibliothèque .NET pure – zéro dépendance
    </h2>
    <p>
     Aspose.Medical pour .NET est entièrement écrit en C# géré et est fourni sous la forme d'un seul assembly sans binaires natifs ni packages NuGet tiers. Les autres bibliothèques d'imagerie médicale reposent sur des codecs natifs ou des outils externes ; celle-ci non. Tous les codecs de compression d'image (JPEG, JPEG‑LS, JPEG 2000, HTJ2K, JPEG XL, RLE) sont implémentés en .NET, de sorte que la bibliothèque se comporte de la même manière sous Windows, Linux et macOS. Cela la rend adaptée aux conteneurs, aux environnements cloud et à tout déploiement où l'installation de bibliothèques natives n'est pas possible. Le package cible .NET 10.
    </p>
   </div>
   <div class="col-lg-12">
    <h2 class="h2title">
     Anonymiser les fichiers DICOM pour la conformité à la vie privée
    </h2>
    <p>
     La confidentialité des patients est une exigence incontournable dans les applications de santé. Aspose.Medical pour .NET anonymise les données DICOM avec les profils de confidentialité du DICOM PS 3.15. Vous pouvez supprimer ou remplacer les informations identifiantes du patient tout en conservant la valeur clinique des données d'imagerie, et choisir ce que le profil conserve : attributs privés sécurisés, UID, identifiants d'appareil et d'institution, caractéristiques du patient et informations temporelles longitudinales. La <a href="/medical/net/anonymization/">page d'anonymisation DICOM</a> détaille les options de profil.
    </p>
    <div class="codeblock" id="code">
     <h3>
      Anonymiser un fichier DICOM - C#
     </h3>
     <pre><code class="cs">// Load the DICOM file
DicomFile dicomFile = DicomFile.Open("patient_scan.dcm");

// Basic Application Level Confidentiality Profile of DICOM PS 3.15
ConfidentialityProfile profile = ConfidentialityProfile.CreateDefault(ConfidentialityProfileOptions.BasicProfile);
Anonymizer anonymizer = new(profile);

// Anonymize into a new file and save it
DicomFile anonymized = anonymizer.Anonymize(dicomFile);
anonymized.Save("anonymized_scan.dcm");</code></pre>
    </div>
   </div>
   <div class="col-lg-12">
    <h2 class="h2title">
     Rendre les trames DICOM en .NET C#
    </h2>
    <p>
     Aspose.Medical pour .NET rend une trame DICOM sous forme d'image pixel BGRA 32 bits. Le moteur applique l'interprétation photométrique, le LUT de modalité et le LUT VOI (fenêtre et niveau) du jeu de données et dessine les superpositions, de sorte que le résultat correspond à ce que montre un visualiseur. Les pixels sont alors à vous : copiez‑les dans un tampon et transmettez‑les à toute bibliothèque d'imagerie pour enregistrer en PNG, JPEG ou TIFF. Le seul encodeur d'image intégré à la bibliothèque est le PNM. Les pages de conversion montrent le chemin complet pour <a href="/medical/net/dicom-to-png/">PNG</a>, <a href="/medical/net/dicom-to-jpg/">JPEG</a> et <a href="/medical/net/dicom-to-tiff/">TIFF</a>.
    </p>
    <div class="codeblock" id="code">
     <h3>
      Rendre une trame DICOM - C#
     </h3>
     <pre><code class="cs">// Load the DICOM file
DicomFile dicomFile = DicomFile.Open("chest_xray.dcm");

// Render the first frame; LUTs and overlays are applied by the renderer
using PixelImage&lt;Bgra32&gt; image = dicomFile.RenderImage(0);

// Copy the pixels out and hand them to an imaging library
Bgra32[] pixels = new Bgra32[image.Width * image.Height];
image.CopyPixelsTo(pixels);</code></pre>
    </div>
   </div>
   <div class="col-lg-12">
    <h2 class="h2title">
     Transcoder entre les syntaxes de transfert
    </h2>
    <p>
     Les systèmes d'imagerie et les archives nécessitent des syntaxes de transfert DICOM spécifiques. Aspose.Medical pour .NET transcode entre les formats non compressés, JPEG Baseline, JPEG Lossless, JPEG‑LS, JPEG 2000, HTJ2K (High‑Throughput JPEG 2000), JPEG XL et RLE. HTJ2K et JPEG XL sont les deux options les plus récentes du standard DICOM, et sont implémentées en .NET comme tous les autres codecs. Le transcodage est crucial pour l'intégration PACS, la taille des archives et la compatibilité entre systèmes. Voir la <a href="/medical/net/dicom-transfer-syntax-conversion/">page de conversion de syntaxe de transfert</a> et la <a href="/medical/net/jpeg2000/">page JPEG 2000</a>.
    </p>
    <div class="codeblock" id="code">
     <h3>
      Transcoder DICOM en HTJ2K - C#
     </h3>
     <pre><code class="cs">// Load existing DICOM file
DicomFile dicomFile = DicomFile.Open("input.dcm");

// Transcode to High-Throughput JPEG 2000, lossless
DicomFile transcoded = dicomFile.Transcode(TransferSyntax.HTJ2KLossless);

// Save the transcoded file
transcoded.Save("output.dcm");</code></pre>
    </div>
   </div>
   <div class="col-lg-12">
    <h2 class="h2title">
     Sérialisation DICOM vers JSON et XML
    </h2>
    <p>
     Les systèmes de santé échangent des données via des services web, c’est pourquoi Aspose.Medical pour .NET sérialise les jeux de données DICOM vers le modèle DICOM JSON (PS3.18) et vers le DICOM XML (PS3.19), et les analyse de nouveau en jeux de données. Les sérialiseurs fonctionnent sur des chaînes, flux et pipes, de façon synchrone et asynchrone, et une séquence de jeux de données peut être lue un par un sans charger l’ensemble du document en mémoire. Les références de données volumineuses sont résolues via un chargeur extensible, ainsi les gros pixels peuvent rester en dehors du document. Voir les pages <a href="/medical/net/dicom-to-json/">DICOM vers JSON</a> et <a href="/medical/net/dicom-to-xml/">DICOM vers XML</a>.
    </p>
    <div class="codeblock" id="code">
     <h3>
      Sérialiser DICOM en JSON et XML - C#
     </h3>
     <pre><code class="cs">// Load the DICOM file
DicomFile dicomFile = DicomFile.Open("patient_scan.dcm");
Dataset dataset = dicomFile.Dataset;

// Serialize the dataset to JSON (DICOM JSON Model) and to DICOM XML
string json = DicomJsonSerializer.Serialize(dataset, writeIndented: true);
string xml = DicomXmlSerializer.Serialize(dataset);

// Parse both back into datasets
Dataset? fromJson = DicomJsonSerializer.Deserialize(json);
Dataset fromXml = DicomXmlSerializer.Deserialize(xml);</code></pre>
    </div>
   </div>
   <div class="col-lg-12">
    <h2 class="h2title">
     Réseau DICOM via DIMSE
    </h2>
    <p>
     Aspose.Medical pour .NET communique directement avec d'autres systèmes DICOM. La bibliothèque fournit un client DIMSE et un serveur DIMSE pour C‑ECHO, C‑STORE, C‑FIND, C‑MOVE et C‑GET, ainsi que les services N, la négociation d'association avec contextes de présentation et rôles, les fenêtres d'opération asynchrones, la négociation d'identité d'utilisateur et TLS. Les requêtes sont mises en file sur une association et répondues par les gestionnaires que vous enregistrez, ainsi un nœud store‑and‑forward, un proxy de requête ou un test SCP ne nécessitent que quelques classes. Le <a href="https://docs.aspose.com/medical/net/developer-guide/dicom-networking/">guide de mise en réseau DICOM</a> couvre l'API complète.
    </p>
    <div class="codeblock" id="code">
     <h3>
      Envoyer une étude à un PACS avec C‑STORE - C#
     </h3>
     <pre><code class="cs">DicomFile dicomFile = DicomFile.Open("study.dcm");

DicomNetworkClient client = DicomNetworkClient
    .CreateBuilder(new DicomNetworkClientOptions
    {
        Called = "PACS_AE",
        Calling = "CLIENT_AE",
        Connection = new DicomNetworkConnectionOptions
        {
            TargetHost = new IPEndPoint(IPAddress.Parse("192.0.2.10"), 104)
        },
        AssociationNegotiation = new AssociationNegotiationOptions()
            .WithPresentationContext(new PresentationContext
            {
                AbstractSyntax = Uid.CTImageStorage,
                Role = null,
                TransferSyntaxes = ImmutableArray.Create(TransferSyntax.ExplicitVrLittleEndian)
            })
    })
    .Build();

client.QueueRequest(new CStoreRequest(dicomFile.Dataset, TransferSyntax.ExplicitVrLittleEndian));

await client.SendAsync(CancellationToken.None);
await client.StopAsync();</code></pre>
    </div>

   <div class="col-lg-12">
    <h2 class="h2title">
     Gros fichiers DICOM sans grande consommation de mémoire
    </h2>
    <p>
     Les images de lames entières, les séries longues et les études multi‑trames ne tiennent pas confortablement en mémoire. Aspose.Medical pour .NET vous laisse choisir quelle partie du fichier charger : tout lire, différer les éléments dépassant un seuil de taille jusqu'à leur accès, ou les ignorer et ne travailler qu'avec les métadonnées. Lire depuis un flux ou un pipe et écrire de la même façon maintient le flux de données au lieu de les accumuler. Le <a href="https://docs.aspose.com/medical/net/developer-guide/open-dicom-file/memory-management/">guide de gestion de la mémoire</a> explique les compromis.
    </p>
    <div class="codeblock" id="code">
     <h3>
      Lire les métadonnées sans les données de pixels - C#
     </h3>
     <pre><code class="cs">// Elements larger than the threshold are not loaded into memory
DicomFile metadataOnly = DicomFile.Open(
    "whole_slide.dcm",
